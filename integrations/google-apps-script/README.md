# Общий журнал результатов

Основной журнал — кабинет учителя в Yandex Cloud. Уроки за 18 и 21 сентября отправляют ответы через существующий Apps Script. Google Sheets сохраняет исходные строки и дополнительный отчёт «Журнал сайта». Контрольные продолжают использовать существующий серверный способ сохранения.

## Сохранение и повтор отправки

1. Страница сохраняет отправку с постоянным ID в браузере.
2. Apps Script записывает исходную строку в «Ответы», обновляет «Сводку» и передаёт результат серверу.
3. Сервер сохраняет исходный JSON в Object Storage и работу в YDB.
4. Только подтверждение кабинета позволяет странице показать «Работа сохранена».

Если подтверждение потеряно, повтор использует тот же ID и исходные ответы. Он не создаёт новую работу и не меняет оценку учителя. Если ученик изменил ответы после неподтверждённой отправки, интерфейс сообщает, что сохранена ранее отправленная версия. После её подтверждения изменённые ответы можно отправить новой попыткой.

Ответ старого коллектора `OK`, загрузка скрытого iframe или подтверждение только Google Sheets не считаются успешной сдачей. При сбое браузер сохраняет отправку для повтора. При недоступности локального хранилища отправка блокируется с объяснением.

## Настройка Apps Script

`Code.gs` заменяет старый коллектор целиком; второй `doPost` рядом не нужен. В свойствах скрипта:

- `JOURNAL_MODE=teacher`;
- `KODISLOVO_JOURNAL_TOKEN` — ключ серверной интеграции из закрытого хранилища владельца.

Веб-приложение выполняется от владельца таблиц. При изменении кода нужно обновлять существующее развёртывание через **«Новая версия»**, сохраняя URL. Сохранение файла в редакторе само по себе опубликованную версию не обновляет. `doGet` возвращает `service: kodislovo-collector`, `version: 2` и протокол `kodislovo.collector-receipt.v1`.

Обе зарегистрированные таблицы имеют локаль `ru_RU`. Поэтому аргументы формулы в `setTotal_` разделены точкой с запятой. Запятые приводят к `#ERROR!`. Пока открытая часть не проверена, итог остаётся пустым.

На сервере настроены `SHEETS_BRIDGE_WORKSPACE_ID` и `SHEETS_BRIDGE_TOKEN`; ключ передаётся только между Apps Script и сервером. В публичных страницах и этом репозитории его нет. Разрешены только два зарегистрированных источника и их листы «Ответы». Для нового дня требуется отдельно зарегистрировать таблицу на сервере и в `DESTINATIONS`.

## Старые работы и оценки

В исходных таблицах обнаружены 97 учебных работ по 14 кодам заданий и одна техническая строка. Технические строки с классом `ТЕСТ` или кодом `SITE_TEST_*` не импортируются как учебные работы.

`syncNextBatch()` вручную переносит или обновляет отчёт максимум для десяти строк за запуск. Курсор двигается только после подтверждения. Повтор не дублирует работу. Перед первоначальным переносом сохраняются закрытые снимки исходных таблиц; после переноса сверяются ID, количество, даты, классы, ответы и баллы.

Старые таблицы не содержат ключей и результатов по каждому вопросу. В кабинете такая работа имеет исходные ответы с прежним автобаллом и открытую часть для проверки учителем. Массивы и тексты сохраняются также в исходном JSON. Автобалл отмечен как `legacy-client`; пересчёт по ключам контрольных запрещён. Старая колонка «Итог» не заменяет сумму проверенных компонентов. Ошибка её формулы сохраняется в исходных данных и отмечается предупреждением, но не мешает перенести корректные ответы и отдельные баллы.

Дата поступления переносится из таблицы с учётом UTC+5. Если в исходной строке даты нет, при живой передаче используется время приёма сервером; происхождение этой даты явно отмечается в сохранённом источнике. Время на устройстве ученика не подменяет серверную дату.

## Обновление Google-отчётов

После переноса оценки выставляются в кабинете. Лист «Журнал сайта» показывает подтверждённый номер работы, состояние, итог и максимум. Сбой обновления отчёта сохраняет ранее подтверждённую оценку и добавляет сообщение об ошибке.

Отчёт обновляется при отправке и вручную: `restartReportRefresh()`, затем `syncNextBatch()` до результата `processed: 0`. **Фонового триггера нет:** сохранение нового балла учителем само по себе не обновляет Google Sheets. Изменения старых баллов в таблице не перезаписывают оценку кабинета.

`repairFormulasAndSummary()` восстанавливает формулы итогов и сводку последних попыток. Запускается отдельно после резервной копии. Исходные ответы при этом не меняются.

## Проверки и выпуск

Проверены 33 клиентских сценария, включая 9 сценариев Apps Script, и 68 серверных тестов. В рабочем образе Python 3.12 прошли 20 тестов связки. Все 16 страниц загрузились в Edge без ошибок. Живой цикл через Google подтвердил сохранение в кабинете, ручную оценку 2/19, её получение Google-отчётом и повтор с тем же ID без дубликата.

Серверный образ `sheets-20261004-v4` собран на основе прежнего рабочего образа с заменой только шести файлов интеграции. Настройки ресурсов и существующие привязки секретов сохранены, минимальное количество постоянно запущенных экземпляров — ноль. Исходная ревизия `bbasv2t0r7o24ijm3cr3` и её настройки сохранены для отката; откат кода не удаляет результаты.

- Клиент: `assets/js/lesson-submitter.js` и 16 страниц в `assignments/2026-09-18`, `assignments/2026-09-21`.
- Apps Script: `integrations/google-apps-script/Code.gs`.
- Backend: `sheets_import.py`, `sheets_bridge.py`; маршрут в `main.py`; защита пересчёта в `service.py`; исходная дата в адаптерах `repository.py` и `ydb_repository.py`.
- Проверки клиента: `node --test tests/*.test.js`.
- Проверки сервера: `python -m pytest -q` в проекте backend.

Снимки таблиц, ключи, исходные JSON учеников и квитанции переноса хранятся вне публичного репозитория.

Поведение развёртываний описано в [Google Web Apps](https://developers.google.com/apps-script/guides/web), перенаправления ответов — в [Content Service](https://developers.google.com/apps-script/guides/content#redirects). Чтение JSON-подтверждения после перенаправления дополнительно проверено настоящим запросом из браузера.
